# Local K-06 acceptance

Run `test/frost/run-k06.sh <evidence-directory>`. It uses the K-05 environment
from `K05.md`. `FROST_K03_TBTC` must point at a compiled tbtc-v2 worktree with
the C-04 stack (C-07, C-05, C-04), K-05 and the K-06 TypeScript change. K-06
changes no contract. A direct Go run skips the external fixture when its
dependencies are absent, and that skip does not establish K-06.

## What the fixture does

`newK06World` is the K-05 world without its test-only funding. It runs:

- the real contracts in `deploy.cjs` `k05` mode;
- a real 1/1/2 DKG with the hash-pinned worker, through public approval to ReadyUnfunded;
- Bitcoin Core 29.0 on regtest.

Custody is funded only by K-06 sweeps. Every step uses production code on each
operator's real encrypted store and worker:

| Step | Code |
| --- | --- |
| Deposit address and refund data | `deposit.Build` (D-04 template), compared with C-05 `frostDepositConstruction` byte for byte |
| Planning | `deposit.Planner`, from finalized C-05 state at the round's anchor block |
| Authorization at every grant | `deposit.Authority` with the K-04 executor |
| Main purpose lock (VD-07) | `deposit.MainLock` and `deposit.Guard`, also taken by the K-05 attester |
| Signing, broadcast, quarantine | `deposit.Sweeper` |
| Sweep-resolution certificate | `deposit.ResolutionAttester` |
| SPV proof and credit | `spv.FrostSweepMaintainer` |
| Depositor refund | `deposit.Refund`, from C-05 `frostDepositRefundConstruction` and the refund key only |

## Named tests

| Test | Acceptance check |
| --- | --- |
| `TestFrostDepositSweepAndCredit` | Two Go-built deposits are funded and revealed. Every operator plans the same sweep from chain state alone. The real worker signs each BIP342 input (one launch per input per operator). Core accepts the sweep; the maintainer proves it. C-05 credits amount − treasury fee − fee share for each deposit, and the treasury receives its fees. A second proof is not submitted. A K-05 payment then spends the main, and the next sweep spends the payment's change as main. Its proof reply is lost; the maintainer settles it by rereading C-05, without resubmitting, and the credit happens once. |
| `TestDepositorRefundWithoutOperators` | The refund is built from C-05's historical refund construction and the refund key, with no operator. Core refuses it before median-time-past passes the locktime (non-final) and accepts it after. No worker runs. A plan made before the refund is abandoned. The refunded deposit is never planned again and never credited. |
| `TestDepositTemplateCrossLanguage` | Go equals C-05 (receipt, leaves, root, C-07 output key and parity, both control blocks) for the real wallet Q across 4-byte and 5-byte CScriptNum locktimes and amount edges. Both refuse a block-height locktime. Core spends a deposit with a 4-byte locktime by the authorized sweep, and a deposit with a 5-byte locktime by the refund. |
| `TestLateDepositRecovery` | **Dead sweep (VD-07 reading 2):** a main-spending sweep is signed but not broadcast, then its deposit is refunded. The sweep purpose keeps the main: a redemption attestation is refused with `ErrMainBusy`. A new sweep alternative without the refunded deposit spends the same main and is credited. Once that is final the old main closes, and a redemption reserves the new main. **Late signature:** median-time-past crosses the refund margin after the workers return and before acceptance. Every operator quarantines the signature, nothing reaches Bitcoin, and the depositor refund settles the deposit with no credit. |
| `TestMainPurposeLockAndResolution` | A reserved main refuses an ordinary sweep. A deposit-only sweep is credited beside it. Every operator's resolution attestation runs inside the first durable payment claim, after the payment's start-time checks. The grant-time lock check then refuses every payment grant, and no worker starts. The resolution sweep spends the reserved main and is proven through C-04 `submitFrostSweepResolutionProof`. The reservation becomes ConflictResolved and the request is refunded in full. |

### Guard regressions

Each regression below reverts one guard in production code. Its named test then
fails. The recorded run is in the evidence directory (`controls.log`).

| Reverted guard | Failing test |
| --- | --- |
| Refund margin in `View.Sweepable` (P-K06-REFUND-RACE) | `TestLateDepositRecovery` |
| Grant-time lock check in `Guard.Grant` (P-K06-ONE-MAIN-PURPOSE) | `TestMainPurposeLockAndResolution` |
| Sweep refused on a main held by another purpose | `TestMainPurposeLockAndResolution` |
| Attester takes the main lock | `TestLateDepositRecovery` |
| Credited sweep not resubmitted (P-K06-CREDIT-ONCE) | `TestFrostDepositSweepAndCredit` |
| Lost reply settled by reread, not trusted | `TestFrostDepositSweepAndCredit` |
| Refunded deposit not planned again | `TestDepositorRefundWithoutOperators` |

### Unit tests

- **`pkg/bitcoin`:**
  - script-path snapshots: digests, witnesses, virtual size;
  - refusals: foreign Q, uncommitted leaf, OP_SUCCESS, code separator, extra signature opcodes, non-minimal pushes.
- **`pkg/frost/signing`:**
  - sweep plans: the C-05 fee split, caps, immediate finality, main order, the input cap;
  - the sweep authority at start, after the claim and after each signature;
  - late quarantine;
  - no rebroadcast.
- **`pkg/frost/deposit`:**
  - the C-05 profile vectors and the BIP341 NUMS key;
  - refund construction and the CLTV binding;
  - planner selection and the main rule;
  - every authority refusal;
  - main lock transitions and the ordering of a stale grant against a resolution.

## Not covered

- **Permissionless discovery of sweeps on Bitcoin.** The maintainer proves a sweep the host names.
- **Production Bitcoin providers.** Median-time-past (A-K06-MTP), funding-output state and script discovery come from Core in the fixture.
- **Fee escalation of a sweep, and reorganizations beyond the canonical-hash checks.**
- **Executed power loss, the production fence and storage class.**
- **V-07.** The model is checked before K-06 merges; the replay runs at the K-06 exit (KC-VER). Hooks are fixed in `pkg/frost/deposit/verification/BOUNDARIES.md`.
