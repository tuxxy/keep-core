## #81 Recover against late reconstruction: resolved

The model now separates two cases:

- Loading an existing aggregate.
- Reconstructing an absent one. Reconstruction rereads the reservation at
  phase 27, then either runs the six-stage aggregate commit or refuses a late
  Done set and keeps Done.

TRANSITION-MAP.md has one row per case. The changes:

- New weakening ReconstructWithoutReread.
- W-done-only-recovered redefined.
- New witness W-done-only-late-refused.

A dead-variable quotient for terminal attempts with retained Done reduced the
state space.

The whole run took 203 s and peaked at 10.9 GB RSS, under the 900 s and
20 GiB ceilings. Before the change the model had 140,043,852 claim states.

## #82 Generated traces in the subprocess driver: partly resolved

`TestV04GeneratedTraceProcessReplay` replays all 25 traces with 284
comparisons:

- 7 are full at application boundaries. These are the controls
  ReleaseBeforeFinality, OmitExactPlan, OmitFinalGuard, ForgetDurableReceipt,
  CancelledRetention, AggregateOnlyRecovery and ReconstructWithoutReread.
- 16 are partial.
- 2 are none: AllowConcurrentReservations (ledger only) and
  EmptyAuthorizationStartsWorker (no Run seam).

Two negative controls (mutated traces) fail at the named comparison.

The witness traces stop where their discovered path starts a second attempt
while the first one is still running, or at `Deliver`. Still open:

- storage-stage lockstep;
- interleaved attempts in one host process;
- `Deliver`/`Broadcast`;
- `Retry`;
- the C-04 ledger;
- host power loss.

## #80 Shared host kernel: plan only

The plan is in SCOPE-2026-11-06.md. Reusing the store kernel inside the V-04
model does not fit the limits, and that code belongs to another agent. The
smaller correct option is to discharge A-STORE in V-05:

- Every signing record is a store claim (`Scoped.Claim("sign")`), already
  covered by S-K02-HOST-3 and S-K03-STORE-2.
- The over-approximation argument for crash scope and pre-ack effects carries
  the rest.
- One store-owned `signing` profile is needed for `signing.go`'s
  identical-resync branch. Its runbook is in SCOPE-2026-11-06.md.

#80 stays open.
