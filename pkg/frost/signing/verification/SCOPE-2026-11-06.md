## #81 Recover against late Done-only reconstruction

### Concrete behaviour (executor.go at 925103a6)

`LoadResult`:

- R1, aggregate record present. It decodes the record and runs `ValidateResult`
  and `checkResultReceipt`. There is no reservation reread and nothing is
  written.
- R2, aggregate absent: `recoverCompletedResult`. It reads the intent (exact
  bytes), the durable receipt and every input's Done record, verifying each
  context. Then it runs `reservation(ctx, false)`: the same check as Run's
  `before-done-accept` reread, including the retained-receipt anchor.
  - On refusal it returns `ErrLateSignature` (or the unread-reservation error
    when the read itself fails). Nothing is written and Done stays retained.
  - Otherwise it assembles the transaction, runs `ValidateResult`, then
    `RetainSigningRecord(resultID)`: one application commit.
- No path obtains a signing grant.

### Corrected correspondence (proposed, not in KC-VER)

| Model | Concrete |
| --- | --- |
| `Recover(i)` offered when attempt `i` is terminal, has retained Done and is not recovered | caller invokes `LoadResult` |
| aggregate present: `recovered := true` | R1 |
| aggregate absent: attempt re-enters phase 27 with `recovering := true` | R2 begins |
| `Step` at phase 27 while recovering: `authorized()` is the reread; refusal makes the attempt terminal with `late_refused := true` and Done kept; Run's earlier caller cancellation is ignored (new call) | `reservation(ctx,false)`, `lateUnlessUnread` |
| `Step` 27..32 while recovering: the aggregate commit, six stages, journal ownership as in Run | `RetainSigningRecord(resultID)` |
| phase 32 while recovering: `aggregate, recovered, reconstructed := true` | result returned |
| `Crash`/`IoError` during 27..32: terminal, Done retained; `Recover` may be offered again | interrupted call; retry |
| `CancelCaller` is not offered while recovering | a cancelled recovery call fails like an I/O error, which is offered |

A read failure of the reservation is not a separate model action. It is the
`IoError` already offered at phase 27.

### Predicate, weakening and witnesses (proposed, not in KC-VER)

- **P-K04-DURABLE-SIGNATURE-RECOVERY** (model-local, SCOPE.md) gains one clause:
  Done-only reconstruction writes an aggregate only after a reread finds the
  reservation authorized with the retained receipt. Otherwise it refuses and
  keeps every Done record.
  - Observer: `bad_recovery` is set when a recovering attempt passes phase 27
    while `authorized()` is false.
- Weakening **ReconstructWithoutReread**: recovery skips the reread. Target
  P-K04-DURABLE-SIGNATURE-RECOVERY.
- Weakening **AggregateOnlyRecovery** keeps its target. Its observer now flags
  only a refusal of a reconstruction the claim model would allow (authorized
  at the reread). Refusing a late one is correct behaviour.
- Witness **W-done-only-recovered** is redefined: an aggregate written by
  reconstruction (`reconstructed && aggregate && retained`). The old form
  (`recovered && !aggregate`) described the mismatch itself.
- New witness **W-done-only-late-refused**: a reconstruction refused at the
  reread, with Done retained, no aggregate and the reservation timeout-pending.

### State reduction (verification-agent self-review)

Once an attempt is terminal with Done retained, `died`, `io_failed` and
`cancelled` are dead variables:

- Only the RECOVERY property reads `died` and `io_failed`, and only for an
  attempt without retained Done.
- `cancelled` is read at phase 21 and phase 27 of a running Run, and by
  `CancelCaller`'s guard. A terminal attempt runs neither; recovery ignores
  Run's cancellation.
- The witness `W-cancelled-return-retained` is reached before the attempt is
  terminal.

So these three are normalized to false in that case, like the existing
terminal program-counter quotient. `recovering` is cleared on terminal.

The change and the reduction were first measured together in a scratch copy at
a smaller tick bound (two ticks, claim configuration only, not evidence):

| Model at two ticks | Unique states | Peak RSS |
| --- | --- | --- |
| before | 113,215,299 | 11.98 GB |
| after | 78,574,083 | 8.48 GB |

The full bound was therefore expected to fit in 900 s and 20 GiB.

## #82 Generated claim-model prefixes in the subprocess driver

### Protocol (proposed harness record)

A new test, `TestV04GeneratedTraceProcessReplay`, reads each generated trace.

- Which steps it replays:
  - a weakened trace: its `claim_model_steps`, cut at the first `diverges`
    step (KC-VER H-06);
  - a claim-model trace: its `steps`.
- Child processes. It runs the existing `TestV04ProcessReplayChild` (real
  executor, real encrypted store, separately durable test fence). There is one
  child per attempt slot at a time. Slot 1 uses a fresh agreed session.
- Environment actions:
  - before the first `Start`, they set the child's initial reservation view
    (unfinalized, changed, re-anchored, timeout-pending);
  - after it, they are applied as decisions at the next pause. A pause precedes
    every concrete guard read (`before-worker-start` before the grant and
    `after-signature` before the post-done reread). A change delivered at any
    pause before the next guard is therefore seen by that guard, exactly as in
    the model.
- Each concrete pause has a model phase:

  | Pause | Phase |
  | --- | --- |
  | `receipt-durable`, `reservation-seen`, `before-intent-record` | 7 |
  | `intent-durable`, `before-defense-record`, `defense-durable` | 13 |
  | `claim-durable`, `before-worker-start` | 19 |
  | `worker-returned`, `transport-cleanup` | 21 |
  | `done-durable`, `after-signature`, `before-done-accept` | 27 |
  | `aggregate-durable` | 33 |

  The driver consumes model steps up to the pause's phase and compares, as
  H-04 requires:

  | Observed in the child | Model state |
  | --- | --- |
  | receipt | `requests[r].receipt != 0` |
  | intent | `requests[r].intent` |
  | claim | `attempts[i].claimed` |
  | Done | `attempts[i].retained` |
  | aggregate | `attempts[i].aggregate` |

- Interruptions:
  - `Crash`, `IoError` and `CancelCaller` act at the last pause at or before
    the model phase where they occur. The step counts as **full** only when
    that phase is the pause's phase.
  - An interruption between pauses is a stage-level loss the store hooks cannot
    stop at: **partial** (H-05).
- After the child stops:
  - its final error is compared with the model's terminal outcome:
    refusal at the grant is unauthorized, refusal at the post-done reread is
    late, success writes the aggregate;
  - `Recover` launches a recover-mode child and compares its outcome the same
    way.
- Stop points (H-05), each recorded with its reason as partial or none:
  - a second slot's `Start` while the first child runs (concurrent attempts in
    one host process);
  - `Deliver`;
  - any C-04 ledger action (`Pay`, `Cancel`, `Refund`) after the first `Start`;
  - `Retry` (weakened only).

### What this leaves open

- Stage-level storage losses between acknowledgements. The store model's
  stages are not hooks in the executor.
- Interleaved attempts in one host process.
- `Deliver`/`Broadcast` and the C-04 ledger actions. The C-04 projection
  remains separate and partial.
- Host power loss. A process kill keeps OS caches; the trace's process and
  host crash kinds are both replayed as a kill, so a host crash is partial.

## #80 Shared host storage kernel versus A-STORE

### Options

1. **Reuse the store crate's kernel**, with signing state as a component
   extension. The V-04 claim model alone is 140,043,852 states at about
   16.5 GB. The store claim model is 34,719,463 states at 7.6 GB, with two
   processes, two images, a clone, a fence reset and three commits.
   - Adding the kernel's per-process image, durability and fence state to
     every V-04 commit multiplies the V-04 space; it cannot shrink it. Even a
     factor of 2 exceeds 20 GiB, so this does not fit the brief's limits at
     the V-04 bound.
   - Reducing the V-04 bound (one request or one attempt) would lose
     W-fresh-after-failure and the no-double-outcome race.
   - It also needs changes in `pkg/frost/store/verification/`, which another
     agent owns.
2. **Discharge A-STORE compositionally in V-05** (chosen; smaller and
   correct).
   - Every V-04 application commit is a store claim. `RetainSigningRecord`
     calls `Scoped.Claim(id', "sign", payload)` under the domain
     `keep-core/frost/signing-record/v1/`; the attempt claim is the engine's
     store claim. On `ErrClaimed` it compares the bytes and calls
     `syncCurrent`.
   - V-01 already covers these claims at bound B1: S-K02-HOST-3 (P-K02-OWNER,
     -TERMINAL, -IMMUTABLE, -DURABLE, -UNCERTAIN) and S-K03-STORE-2. Both are
     fresh at 925103a6 according to the verification manager.
   - The only unmodeled store code on this path is `signing.go`: the domain
     separation and the identical-resync branch. S-K02-HOST-3 pins it as "not
     modeled".

### A-STORE split into checkable clauses (proposed, not in KC-VER)

| Clause | V-04 use | Producer |
| --- | --- | --- |
| A-STORE-1 an acknowledged signing record survives process and host crash, or the reopen quarantines | receipt, intent, claim, Done and aggregate flags persist | P-K02-DURABLE |
| A-STORE-2 an acknowledged record is immutable; an identical retain re-establishes durability; a conflicting retain fails | receipt anchor pinning, intent bytes, identical recovery writes | P-K02-IMMUTABLE plus the `signing.go` extension |
| A-STORE-3 an acknowledged claim is terminal across release, restart and stale restore | TERMINAL-ATTEMPT (claim at stage 18) | P-K02-TERMINAL |
| A-STORE-4 one live owner; commits serialize | `journal_owner` | P-K02-OWNER |
| A-STORE-5 a fence commit with a lost reply never lets the process continue | `IoError` at every stage | P-K02-UNCERTAIN |
| A-STORE-6 an unacknowledged write may or may not survive; it never grants authority | pre-ack effects are absent in the model, except the claim under process crash | see "Over-approximation" |

### Over-approximation of crash scope and pre-ack effects

The V-04 model crashes one attempt at a time. Both attempts concretely share
one host process, so a real process or host crash ends both.

- Every joint crash is reachable in the model as consecutive `Crash` actions
  with no step between, so the model has a superset of the concrete crash
  behaviours. Safety properties checked on that superset hold for the subset.
- A pre-ack record that survives concretely can only add refusals or recovery:
  - a surviving receipt anchors a later attempt more tightly;
  - a surviving intent, Done or aggregate adds recovery data and grants
    nothing.
- The witnesses rely on no crash.

This argument is verification-agent self-review. V-05 should cite it in the row
alongside the producer statements.

## Rev 02 predicates (not in this task)

- REBROADCAST-THEN-CANCEL: the #81 correction makes it easier. `Rebroadcast`
  requires a durable aggregate, and the model now writes one only while
  authorized (Run) or after an authorized reread (reconstruction). A late Done
  set stays without an aggregate, which is the state a rebroadcast predicate
  has to exclude.
- The reworded LATE-SIGNATURE-QUARANTINE: easier. `W-done-only-late-refused`
  is the recovery-side quarantine witness, and the #82 driver replays the
  reread refusal in a real process.
- RECOVERY-RESERVE: easier. The reconstruction commit now has stages.
- CONTAINMENT-NEEDS-DIRECTIVE and IMMEDIATELY-FINAL: unaffected.
