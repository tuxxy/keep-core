# Local K-04 acceptance

Run `test/frost/run-k04.sh <evidence-directory>` after the K-03 contracts are
compiled. Keep the K-03 environment from `README.md`, and add:

- `FROST_K04_BITCOIND`: absolute path to Bitcoin Core 29.0 `bitcoind`.
- `FROST_K04_BITCOIND_SHA256`: reviewed hash of that executable.

The script fails if required environment variables are absent. Direct Go test
runs skip the external fixture when its dependencies are absent; that does not
establish K-04 acceptance. No dependency or protocol upgrade is required.

The real fixture creates a private regtest data directory, disables P2P,
uses an authenticated loopback RPC port, and stops its own daemon on exit.
It uses actual K-03 contracts, real worker processes, encrypted journals and
libp2p with seat allocation 1/1/2. It funds two exact-Q outputs with regtest coins,
finds a leading-zero input digest, signs through `tbtc.ExecuteFrostTransaction`,
checks the actual durable worker grants against the builder's intent and hashes,
refuses a post-claim reservation flip before any worker launch, validates
BIP340 and the Bitcoin script, calls Core `testmempoolaccept`, broadcasts,
and mines the transaction. Both operators retain the same signed bytes.
The reservation provider is controlled; C-04 contract acceptance is not claimed.

## Pinned external fixtures

The local run uses Bitcoin Core 29.0 for arm64 macOS from
https://bitcoincore.org/bin/bitcoin-core-29.0/ . The archive
`bitcoin-29.0-arm64-apple-darwin.tar.gz` has SHA-256
`34431c582a0399dd42e1276d87d25306cbdde0217f6744bd55a2945986645dda`,
matched against the release `SHA256SUMS`. The executable SHA-256 is
`f4b9d78a74643c726d022840ca506dc317d41f8825aaef80b7bb705e12c5fda8`.
Neither archive nor executable is committed. Other platforms require their own
reviewed executable pin. The runtime fixture checks both the pin and version.
The BIP341 vector source and exact source revision are recorded in
`pkg/bitcoin/testdata/BIP341-SOURCE.md`. The worker remains the K-03 pinned binary.

## Evidence and limits

See `K04-RESULTS-2026-10-07.md` for completed checks and source hashes. This is
local implementation acceptance. V-04 bounded model checking and correspondence
review are pending and gate merge. Full V-04 replay against C-04 gates K-05 exit.
SF-03 capacity, the production memory budget, D-01 packaging, runtime/fence and
other release decisions remain open. No production activation is included.

The review test uses a test-only shell launcher that writes a start marker and
then executes the exact hash-checked worker. The same launcher completes the
positive signing control. This makes even a brief unauthorized spawn observable.
The worker binary and its protocol stay unchanged.

Cross-operator agreement on session, start block, selected seats and executor
configuration is deferred to K-05. The fixture supplies agreed values; passing
this test does not establish a FROST coordination protocol.
