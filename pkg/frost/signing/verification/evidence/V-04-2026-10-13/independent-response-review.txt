RESPONSE TO ORIGINAL FINDINGS

F1 — fixed in executor.go:291–317, particularly 312–315.
The executor verifies a returned signature, creates a persistence context with
context.WithoutCancel plus a 30-second timeout, retains Done through the same
fenced immutable journal, and only then closes the transport. The persistence
context preserves caller values and does not inherit caller cancellation.
Engine-return cancellation and transport-cleanup cancellation both retain a
cryptographically valid Done in the real encrypted store. Timed-out completions
remain unavailable for authorized fallback/broadcast. The independent context
probe confirms a deadline and preserved values. Source sets it to 30 seconds;
no 30-second wall-clock timeout experiment was performed. This is a cooperative
context deadline, not a hard interruption of an unresponsive I/O syscall/provider.
Actual persistence failures still return an error and preserve terminal claims.
The fix closes loss caused solely by cancellation; it does not claim impossible
retention guarantees after actual storage failure or process death before a write.

F2 — fixed in executor.go:372–375 and 400–453.
Only ErrMissing for the aggregate activates fallback. Fallback requires exact
original intent bytes, a valid durable receipt, all original per-input Done
records, strict decoding, exact expected contexts and BIP340 verification. It
rechecks current reservation and immutable receipt before AddSignatures, validates
the reconstructed transaction, and retains the aggregate. It never calls the
engine. Existing aggregate corruption is rejected rather than silently bypassed.
Full two-input completions recover after real store close/reopen; the next load
returns byte-identical witness serialization. One-of-two completion data refuses
without retaining an aggregate or granting the missing input. Original attempts
remain claimed and cannot be rerun. Parent one-input and multi-input regressions
also pass independently.

ADVERSARIAL RESPONSE CHECKS

All final assertions passed. No new confirmed findings.

1. Multi-input recovery: one-of-two refuses, two-of-two recovers after real
   encrypted-store reopen, validates and broadcasts exact bytes. Signature
   counts do not increase. A same-attempt Run still receives ErrClaimed.
2. Missing/malformed anchors: absent intent, absent receipt, invalid zero receipt,
   changed intent, missing first Done and missing second Done all refuse; no
   aggregate is created.
3. Mixed completions: a whole input-zero Done inserted at the input-one lookup,
   plus mismatched input, attempt, plan, reservation, wallet, descriptor, Bitcoin
   network, purpose, start block and digest all refuse. Corrupt signature,
   malformed JSON, unknown field and trailing Done data refuse too.
   These record-corruption cases use a controlled read wrapper over the real
   journal; no encrypted files or parent records were mutated.
4. Reservation changes immediately before fallback's final read: timeout,
   changed receipt block/hash, commitment, generation or state version,
   insufficient finality and orphaned block all return ErrLateSignature and
   create no aggregate. No engine call occurs.
5. Aggregate persistence: cancellation and a controlled persistence error return
   nil result plus error. Retry with a fresh context succeeds from the already
   retained Done records without a new signature.
6. Real store fence errors: failed fence advancement and committed advancement
   with a lost reply both poison the live store and return no result. After
   close/reopen, a failed advancement loads the older acknowledged head, excludes
   the orphan aggregate, and successfully reconstructs it from acknowledged Done.
   A committed advancement with a lost reply loads and verifies the committed
   aggregate. No engine grant occurs. Opening the prior nonzero valid fence head
   is correct; refusing to acknowledge the orphan is the safety requirement.
7. Returned Done persistence failure: cleanup runs exactly once, Run returns nil
   plus the storage error, and the real engine-attempt claim remains terminal.
8. Reservation timeout inside aggregate persistence: the completion remains
   retained, but actual Broadcast refuses with ErrUnauthorized and sends no
   bytes. Retaining a completed result is not a fresh signing grant or settlement.
9. Malformed existing aggregate: returns error directly without consuming fallback
   records or calling an engine. Fallback is confined to missing aggregate data.
